# 2026-09-12 产品表单「广播ID」改名为「涂鸦产品ID」

- 范围：flowerpot-web（Vue 3 + Element Plus 后台）
- 环境：SSH 开发机 `/pgdata/pg/dh/flowerpot-web`
- 分支 / 起点：`main` @ `4e7f2e1`

## 需求

产品：「将新增/编辑/详情产品，将广播ID 的文案改成 涂鸦产品ID，备注写下是用的旧的广播ID字段。」

## 改动

只动了 `src/views/sms/productList/template/DetailForm.vue` 一个文件——新增、编辑、详情三个页面
（`add.vue` / `edit.vue` / `detail.vue`）引的都是它，所以一处改完三处都变。

- `el-form-item` 的 `label`：`广播ID` → `涂鸦产品ID`。
- 输入框 `placeholder`、必填校验的 `message`：同步改成「请输入涂鸦产品ID」。
- 输入框下面加一行备注：**「备注：沿用原「广播ID」字段（broadcastId），后端字段名未变。」**
  配一个 `.form-tip` 样式（`el-form-item__content` 是 flex + wrap，给满宽就会自己换到下一行）。
- **`prop` / `v-model` / 提交字段一律没动，还是 `broadcastId`。** 后端表结构和接口出入参都没改，
  App 侧读的也还是 `broadcastId`。模板里和 `getData()` 的注释都写明了这一点，免得后面有人
  「顺手把字段名也统一一下」。

产品列表页 `index.vue` 没有这一列，全仓库搜「广播」只剩上面那行备注。

## ⚠️ 留给 App 侧的风险（未改代码，仅记录）

这个字段的**语义**和 App 的用法要对上，否则以后新增产品会认不出来：

- App 侧 BLE 扫描拿到的 `ScanDeviceBean.getProductId()`，2026-09-11 真机实测是
  **`ehbx83xdh9jkmxvz`**，也就是**广播包里的标识**；涂鸦平台上的产品 ID 是
  **`yciq4kssu1fv8umn`**，两者不是同一个值。
- `FlowerpotState._isOurProduct` 的判据是：`TuyaConfig.productId` / `TuyaConfig.broadcastId`
  两个本地常量兜底，再加上后台 `/Client/Product/getProductList` 每条的 `broadcastId` 集合。
- 所以**当前这款花盆不受影响**（本地常量里两个值都有）。但如果以后新增产品时，运营按新文案
  在这里填的是涂鸦平台产品 ID 而不是广播 ID，**App 的搜索页就配不上那台新设备**。
- 要么运营继续填广播 ID（文案改了、含义没变），要么后端另加一个字段、App 侧两个都比。
  需要产品拍板，本轮没动代码。
