# 产品新增/编辑/详情恢复「广播ID」，改为必填

> 文档类型：Historical Change Record
> 日期：2026-09-11
> 环境：SSH
> 分支与起始版本：main / `2edcd5e`
> 范围：`src/views/sms/productList/template/DetailForm.vue`
> 相关：`docs/history/2026-09/2026-09-08-module-cleanup-and-product-field-trim.md`（当初撤掉它的那一轮）

## 背景

产品要求：产品**新增 / 编辑 / 详情**三个页面各加一个表单项，字段名 `broadcastId`，**必填**。

这其实是**把 2026-09-08 撤掉的字段恢复回来**。那一轮精简产品表单时，把形状类型、屏幕方向、
尺寸、广播ID、轮播间隔、旋转度数一起从界面上去掉了，并在记录里留了风险提示：

> **广播ID**：它是后台产品与涂鸦 PID 的映射来源，界面上去掉后，新建产品不会再提交这个
> 字段；若后端把它当必填，新增会失败——需要后端确认，或改由后端/数据库维护。

现在按产品要求恢复，这条风险就此关闭。

## 为什么这个字段重要（App 侧同日查清）

`broadcastId` 与涂鸦平台的**产品 ID 是两个不同的字段**，不是一回事：

| | 是什么 | 谁用 |
| --- | --- | --- |
| `productId`（如 `yciq4kssu1fv8umn`） | 涂鸦 IoT 平台上那个**产品**的 ID | 配网、绑定、DP 表——**云端一律以它为准** |
| `broadcastId`（如 `ehbx83xdh9jkmxvz`） | 设备**广播**时放进 BLE 包里的标识 | 只用于本地判断「这条广播是不是这款产品」 |

花盆 APP 做蓝牙配网时，BLE 扫到的 `ScanDeviceBean.getProductId()` 拿回来的正是
**广播里那个**。所以后台这个字段一旦缺失，App 就认不出扫到的是不是本产品。

## 变更内容

三个页面共用 `template/DetailForm.vue`（`pageType` 1=新增 / 2=编辑 / 3=详情），所以只改一处：

1. `defaultForm()` 加 `broadcastId: ''`；
2. `rules` 加 `broadcastId: [{ required: true, message: '请输入广播ID', trigger: 'blur' }]`；
3. 详情回填补 `broadcastId: detail.broadcastId ?? ''`
   ——`?? ''` 不能省：后端返回 null 时 `Object.assign` 会把默认值覆盖成 null，`el-input`
   拿到 null 会告警，必填校验也判不出「没填」；
4. 模板里在「产品名称」之后、「产品图片」之前插入 `el-form-item`，
   `:disabled="pageType === 3"` ⇒ 详情页只读，与同页其它字段一致。

`getData()` 上方那段注释同步改准确：广播ID 已经重新上界面，不再属于「界面不展示、
仅原样回传」那一类。
