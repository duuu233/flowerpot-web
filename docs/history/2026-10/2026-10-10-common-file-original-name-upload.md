# 文件管理上传保留原始文件名

> 文档类型：Historical Change Record
> 日期：2026-10-10
> 环境：家庭
> 分支与起始版本：main / 5f0684a
> 范围：文件管理表单与公共上传接口选项
> 当前权威文档：[文件管理](../../common-file-management.md)

## 背景与目标

产品要求新增文件模块上传时携带 isSaveOldFileName=1，保留原始文件名；返回名称回填页面且禁止手工修改。
原表单仅支持手填名称与地址，没有上传入口。本轮开始时工作区干净，先 pull 当前 main，已是最新。

## 变更内容

- src/api/oss.js：setFileUpload 增加可选 isSaveOldFileName 查询参数，保留 isUploadThumb 和默认调用行为。
- src/views/sms/commonFile/CommonFileFormDialog.vue：新增单文件上传，传 isSaveOldFileName=1；成功标准化 retData 并回填 name、url，文件名称只读，提交保留原始名称。
- 上传时阻止保存、取消、关闭及表单编辑；失败或缺失地址保留旧值。编辑可重新上传，更换后的名称与地址一起提交并保留 fileId。
- 更新当前模块约定及文档索引，保留上一轮模块创建历史。

## 关键决策

仅文件管理开启保留原始名称，其他业务上传不增加默认参数；不修改认证、签名和统一请求层。
沿用文件名 20 字符、地址 120 字符的既有保存校验，不截断或重命名。
地址继续允许编辑；文件名由上传结果产生，缺失 name 时回退所选文件名。上传成功不自动保存业务记录。

## 外部操作

仅 Git 同步、提交和推送；未改后端菜单、权限、依赖或环境配置。
验证使用本地隔离模拟上传响应，没有向线上上传或新增、编辑、删除真实文件记录；未发布、部署或重打 ZIP。

## 验证结果

- node --check src/api/oss.js 通过。
- npm run build 通过（最终 13.91 秒）；第三方 VueUse 的既有 PURE 注释警告不影响构建。
- 无头 Chrome 使用实际 Vue 表单与公共请求层、隔离模拟上传接口：核验 isSaveOldFileName=1、multipart 中文原始文件名、只读名称阻止键盘改名、name/url 回填、必填提示指引上传、超长原名保持完整并阻止保存、上传期间禁用、失败和缺失地址保留原数据、新增/编辑保存载荷及 fileId。
- 默认上传不携带保留原名参数；缩略图调用仍携带 isUploadThumb=1，未被新增选项影响。浏览器无未捕获异常。
- git diff --check 和变更文件信息隔离检查通过。

## 未完成项与风险

未对真实上传服务或保存接口进行写入验证，需上线前用测试文件核实服务端保留原名行为。
同名文件冲突策略由上传服务决定；超过既有字段长度的文件无法保存，本轮未变更后端限制。

## 回滚或恢复

回退本次提交可恢复手填名称、地址的旧表单以及旧上传选项；不存在本轮真实文件数据需要恢复。
